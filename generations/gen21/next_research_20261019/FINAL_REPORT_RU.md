# Gen21, раунд 3: итоговый отчёт (dev)

Задача: `../INSTRUCTIONS FOR NEW IDEAS ROUND 3.md`. Нужно предсказать log SF соседних лантанидов
(strict-adjacent, |ΔZ| = 1) по **четырём** измеренным металлам (k = 3). Основной режим (`PROTOCOL.md` §1):
V1, когорта C3 (229 ячеек / 1 802 пары на seed), опорная политика DOPT_Q, хемотипный hold-out BP и BPG,
5 dev split seeds. Цель: R² ≥ 0,50 при реальном преимуществе над интерполяцией тех же измерений (PWL).
Протокол и реестр записаны до первого внешнего запуска. Журнал: `ATTEMPTS.md`. Поправки и отклонения:
`AMENDMENTS.md`. Разделы 1–6 описывают **dev**. Однократная финальная проверка на отложенных seeds
выполнена 2026-10-19 с явного разрешения пользователя; её итог — в разделе «Финальная проверка» сразу
после краткой сводки. Ничего не закоммичено и не запушено.

Отчёт написан после независимого ревью (4 направления: числа, утечки, протокол, статистика; каждую
находку перепроверял отдельный верификатор). Утечек и неверных ключевых чисел ревью не нашло. Зато оно
нашло, что правило отбора §7 сначала было применено не полностью. Ниже приведён итог правила в
записанном виде.

## Коротко

* **0,50 при четырёх металлах не достигнуто** ни одной из 28 испытанных конфигураций.
* **Итог правила отбора, применённого как записано:** кандидат основного режима — R02 (PWL плюс
  ridge-корректор по 6 геометрическим признакам), 0,4189 / 0,4199. Его выигрыш над интерполяцией
  +0,001 [−0,002; +0,005] неотличим от нуля. По записанному правилу раунд 3 **не показал проверенного
  обучаемого навыка сверх интерполяции**.
* **Главная описательная находка — один общий параметр «провала у Gd».** Это интерполяция PWL по
  радиусу плюс одно обучаемое число:
  * на DOPT_Q (R14): 0,4518 / 0,4520, выигрыш +0,034 [+0,016; +0,065] к PWL на тех же опорах;
  * на опорах label-free политики POL_ERR (R23; по протоколу это отдельный режим): 0,4748 / 0,4733,
    выигрыш +0,038 [+0,015; +0,074];
  * по пулу из 23 сравнений V1/C3/k = 3 (три baselines B0 и 20 конфигураций) выигрыш переживает
    непараметрическую min-P поправку на множественность (нижняя граница +0,012), но не симметричный max-T
    (−0,002…−0,008). Доказательство есть, но не подавляющее.
* **Почему эта находка не стала кандидатом.** Зарегистрированный контроль §8.6 (перемешивание обучающих
  целей внутри типа пары) сохраняет 86–90 % этого выигрыша. Значит, параметр учит **среднее по типу пары**
  из обучающих ячеек, то есть известный излом ряда у Gd, а не что-то, специфичное для ячейки. Это не
  утечка: все проверки отравления меток и подмены скрытых значений пройдены. Но условие §7(c) R14 и R23
  не выполняют, и правило ради них не меняется.
* **0,50 достигается только в более дорогом режиме** (узкая когорта C6):
  * по среднему по seeds — при 6 измеренных металлах с опорами POL_ERR, причём уже у простой
    интерполяции (0,511 / 0,504), и при 7 металлах с DOPT_Q;
  * по нижней 95 % границе — только при 7 металлах с поправкой Gd (0,514 / 0,518).
* **Финальная проверка (однократно, на 5 отложенных seeds) подтвердила dev-картину:**
  * кандидат правила R02: 0,4224 / 0,4227. 0,50 не достигнуто, выигрыш над PWL_R не подтверждён
    (+0,0002 / −0,0002);
  * вторичные конфигурации (описательно): R14 0,4547 / 0,4542, выигрыш +0,032 / +0,031 над PWL_R;
    R23 0,4713 / 0,4633, выигрыш +0,037 / +0,033. Нижние границы выигрыша > 0 в обоих дизайнах, 5/5 seeds.

* Что это значит. Устойчивый на новом разбиении тех же ячеек прирост +0,03 даёт одно общее число — излом

  он остаётся описательной находкой, а не проверенным навыком. Переноса на новую химию финал не
  показывает: это те же 229 ячеек.

Положительный знак означает, что метод лучше. Интервалы получены хемотипным блочным bootstrap
(номинально 95 %; при ≈ 4 эффективных хемотипах реальное покрытие ниже). Семейная поправка по пулу из 23

Как это читать:
* выигрыш возникает из обучающих меток: если перемешать их по всем строкам, он пропадает;
* но он целиком сидит в **среднем по типу пары**, которое перемешивание внутри типа пары сохраняет.

Где сидит выигрыш (R23, BP; `results/diagnostics/`):
* Eu/Gd: 0,180 → 0,349; Gd/Tb: 0,272 → 0,546. Остальные 10 типов пар почти не меняются;
* пары с обоими скрытыми концами: 0,357 → 0,455 (719 пар на seed); пары с одним прочитанным концом:
  0,472 → 0,481 (1 083 пары);
* DGA sc009: 0,453 → 0,464; не-DGA: 0,415 → 0,473. В отличие от химически обусловленного варианта
  R08/R12, поправка не вредит DGA;
* обученный коэффициент −0,094 ± 0,015 по 25 BP folds. Это близко к провалу у Gd из gen13 D7 (−0,072);
* по абсолютному log D непрочитанных металлов: при POL_ERR поправка почти ничего не меняет (MAE 0,148 →
  0,147), и HBK@ML там лучше обоих (0,141); при DOPT_Q поправка снижает MAE с 0,145 до 0,139 и лучше
  HBK@ML (0,142). Выигрыш в log SF, таким образом, связан прежде всего с **формой** ряда около Gd.

Механизм (вывод, а не измерение): остаток HB-модели близок к случайному блужданию (ρ ≈ 0,986). Условное
среднее случайного блуждания по точечным опорам и есть кусочно-линейная интерполяция, поэтому HB ≈ PWL
(B0: HBK@ML − PWL_R = −0,004 [−0,016; +0,008]). Переносимое знание сверх этого — одно общее число,
средний излом у Gd.

* По среднему по seeds 0,50 достигается при 6 металлах с POL_ERR(k) у всех трёх методов, включая простую
  интерполяцию, и при 7 металлах с DOPT_Q.
* По критерию «каждый seed» при 6 металлах проходит только поправка Gd.
* По нижней 95 % границе 0,50 подтверждается только при 7 металлах с поправкой.
* При 6 и 7 металлах поправка **неотличима от HBK@ML** на тех же опорах: +0,011 [−0,014; +0,038] и
  +0,012 [−0,008; +0,031]. Над PWL_R она выигрывает при любом бюджете (+0,031 [+0,014; +0,050] при

* Сравнение «6 против 7 металлов» смешивает смену политики со сменой корректора. Сама смена опор при

* C6 — более трудная часть C3: на 96 ячейках C3 вне C6 R23 даёт 0,529 / 0,530. Число металлов

## 4. Какие комбинации сработали и какие нет

Описательно сработали (с учётом §8.6 — см. раздел 2):
* **R23 = поправка Gd × POL_ERR**: +0,057 [+0,028; +0,106] к опорной цепочке PWL_R@DOPT_Q. Но от своей
  лучшей части R14 комбинация **неотличима**: R23 − R14 = +0,023 [−0,003; +0,057]; взаимодействие
  +0,004 [−0,002; +0,014].
* **R24 = бюджет × POL_ERR(k) × поправка Gd**: при 6 металлах точечная оценка выше 0,50 во всех seeds,
  но от HBK@ML на тех же опорах поправка неотличима, а нижняя граница ниже 0,50 (раздел 3).
* **R18 = R23 × V2**: выигрыш над PWL сохраняется на очищенных данных (+0,046).

Не сработали:
* R06 (геометрия/позиции × выбор признаков по целевой ошибке) совпал с R03 и не прошёл правило;
* R12 (химический корректор × POL_ERR): +0,005 [−0,021; +0,045], вред DGA. Корректор для R12 был
  выбран с ошибкой в применении правила (D-5): правильным был бы R02, то есть R15;
* R13 и R22 (стекинг; стекинг + корректор): R22 формально проходит (a) и (b), но ничего не добавляет к
  лучшему члену;
* R20 (корректор R08 по бюджету на DOPT_Q): +0,005 при k = 3; при k = 5 +0,006 [−0,010; +0,026] на BP и
  −0,005 [−0,031; +0,025] на BPG.

## 5. Проверки утечек и их пределы

Выполнено (файлы в `results/leakage/`, `results/<ID>/`, `tests/`):
1. **Изоляция folds** (ячейки, экстрагенты, хемотипы, публикации; под BPG — группы копий) проверяется
   assert'ом на каждом fold каждого запуска, включая будущий финальный.
2. **Обучение только на train, полная цепочка, все 50 folds.** Для R02, R14 и R23 весь обученный набор
   (HBK, таблица POL_ERR, корректор, λ) пересчитан при отравлении log D **всех** ячеек вне outer train,
   включая `bench.Y`, через который могут читать замыкания. Выбранные POL_ERR опоры для каждой тестовой
   ячейки тоже сравнены. Результат: **всё совпало на всех 50 folds у всех трёх**; у R23 проверены опоры
   2 290 тестовых ячеек (`poison_chain_*.json`). Кроме того, проходят все контрактные тесты (`tests/`).
3. **Перестройка всего fold cache** с заменёнными held-out labels: все разрешённые поля кэша совпали во
   всех 50 folds (`cache_poison.json`).
4. **Intervention** на всех folds обоих дизайнов для каждой конфигурации: подмена всех непрочитанных log D
   не меняет прогнозов (изменение 0). После ревью вторую проверку ведёт свежий экземпляр политики,
   поэтому проверка опор у POL_ERR действительно может провалиться. Тест с «подглядывающей» политикой это
   подтверждает. Методы второго прохода собираются заново по копии данных с подменёнными значениями, поэтому
   попытка читать скрытые метки при предсказании тоже была бы поймана (второй контрактный тест). Повторно
   пройдено для R02, R14, R23 и всех конфигураций с POL_ERR (R09–R11, R12, R15, R16, R18, R24, CTRL23,
   CTRL23W).
5. **Законность опор:** ни у одной оцениваемой пары оба конца не прочитаны (assert), ровно 4 чтения.
6. **Label-shuffle контроли:** зарегистрированный §8.6 и дополнительный по всем строкам (раздел 2).
7. **Воспроизводимость:** R02, R14 и R23 пересчитаны с нуля финальным (замороженным) кодом на всех 50
   folds и совпали с сохранёнными прогнозами бит в бит (`repro_<ID>_<design>.json`). Перед заморозкой
   вычислительная часть финального runner'а в замороженном виде прогнана на dev-фолде (seed 104729,
   fold 0) для R02, R14 и R23 в обоих дизайнах: строки и опоры совпали бит в бит, intervention пройден
   (`runner_smoke.json`).

Пределы:
* **Зарегистрированный контроль §8.6 не отделяет выученное среднее по типу пары от прочего.** Он это
  среднее сохраняет и поэтому снимает лишь 10–14 % выигрыша поправки в один параметр (вывод из
  контролей, не доказательство). Это недостаток протокола; исправлять его задним числом нельзя.
* **Адаптивный отбор на dev:** 28 конфигураций и 5 изменений реестра после результатов при лимите
  24 / 2 (`AMENDMENTS.md`). Шумовой оптимизм мал, адаптивный не оценивается.
* **Мало независимой химии:** ≈ 4 эффективных хемотипа, интервалы, скорее всего, покрывают меньше
  номинала.
* **Шум log SF неизвестен:** повторяемость соседнего log SF в корпусе не измерена.
* **V2:** правила V2-1/2/3 выведены по происхождению данных. V2-5 — по значениям (отклонение от §9).
  V2 — отдельный бенчмарк.
* Проверено отсутствие утечек, а не перенос на новую химию.

## 6. Что остаётся dev, что проверит финал, какие данные нужны

**Dev — всё перечисленное выше.**

**Направление D: критерий модели против реальной ошибки** (`results/calibration/`, только inner-блоки
outer-train, все 50 folds, ≈ 30 000 пар на дизайн):
* апостериорная дисперсия контраста у HBK@ML плохо предсказывает реальную ошибку inner-validation;
* на уровне строк Spearman 0,09 / 0,10. У идеально откалиброванного критерия было бы ≈ 0,19;
* в верхнем квинтиле дисперсии ошибка даже **меньше**, чем в нижнем: отношение 0,80 против ожидаемых
  2,8;
* средний масштаб завышен на 17–19 % (отношение 0,83 / 0,81);
* **по 12 типам пар порядок обратный**: Spearman −0,71 / −0,57 при ожидаемых +0,86. Модель считает самыми
  неопределёнными Yb/Lu и Tm/Yb, а реально хуже всего Ce/Pr, La/Ce и Eu/Gd;
* верно передано только различие «оба конца скрыты» и «один прочитан». Политика, минимизирующая этот
  критерий, тянула бы опоры не туда. Собственный критерий DOPT_Q (латентная дисперсия) с ошибкой не
  связан вовсе;
* эмпирическая таблица POL_ERR откалибрована по масштабу лучше (0,85 / 0,84; с весами по хемотипам
  0,92 / 0,91), но внутри типа пары почти ничего не различает (Spearman 0,03).

Вывод: выбор опор по модельной дисперсии здесь не годится. Таблица ошибок, обученная на train, лучше,
но её выигрыш над DOPT_Q не доказан (раздел 3).

Ограничение применимости POL_ERR: политика выбирает среди металлов, которые ячейка реально измерила. В
литературном корпусе есть только опубликованные металлы, а на практике лаборатория должна уметь
измерить именно выбранные четыре.

**Финальная проверка (выполнена однократно 2026-10-19; результат — в разделе «Финальная проверка» выше):**
* заморожен R02, кандидат правила §7. Вторичные конфигурации — R14 (поправка Gd на DOPT_Q) и R23 (на
  POL_ERR). В заморозку входят: данные V1, когорта и пары, бюджет, политика, метод, правило λ, сравнения,
  решающее правило, хэши всего кода, который импортирует прогон runner'а (включая ленивые импорты и
  модули gen13sep / gen14 / gen15 / gen6 / gen20k), версии пакетов, dev seeds и коммитмент финальных
  seeds (`manifests/freeze_manifest.json`, печать `93d3839a256c2185…` в `freeze_seal.txt`). `--dry-check`
  пройден;
* `scripts/r3_final_runner.py` проверяет печать заморозки, идентичность кода, хэши входных данных,
  версии пакетов, хэш и формат файла seeds (до записи RUN_ONCE) и однократность запуска. Fold cache финальных seeds строится в отдельной папке. На каждом fold
  проверяется изоляция и intervention;
* решающее правило записано заранее:
  * 0,50 достигнуто, только если у кандидата R² ≥ 0,50 (без округления) и в BP, и в BPG, а MAE лучше
    PWL_R и PWL_Z;
  * выигрыш над PWL подтверждён, только если нижняя 95 % граница ΔR² и ΔMAE > 0 в обоих дизайнах;
  * для R14 и R23 те же числа публикуются описательно: стать итогом раунда задним числом они не могут;
* ожидание до запуска: по dev у R02 около 0,42, у R14 около 0,45, у R23 около 0,47, все ниже 0,50. Так и
  вышло: R02 0,422 / 0,423, R14 0,455 / 0,454, R23 0,471 / 0,463 (BP / BPG). Выигрыш параметра Gd над
  интерполяцией удержался;
* финал проверяет новое разбиение **тех же** ячеек. Переноса на новую химию он не показывает.

**Нужные лабораторные данные** (`EXPERIMENTAL_DATA_REQUEST.md`):
1. Повторы полных рядов La–Lu (≥ 3 независимых прогона) примерно для 6 систем разных донорных классов, с
   полными метаданными и пределами обнаружения по металлам. Это даст потолок шума log SF.
2. Новые экстрагенты не из корпуса (N-гетероциклы, α-замещённые DGA, где провал у Gd отличается), 2–3
   условия, полный ряд. Это внешняя проверка переноса: кандидат и его политика замораживаются до
   получения данных, аналитику выдаются только 4 выбранных металла.
3. Работа с источниками: значение Pr/Nd при 5 M у DMDPhPDA (Shimada et al.), пределы обнаружения для
   серии C5BTBP.

Если нужно 0,50 на практике, сейчас его дают **6–7 измеренных металлов** (C6, dev), а не обучение. При
четырёх металлах ни один из испытанных путей до 0,50 не дошёл. Единственный устойчивый обучаемый
прирост — общий излом у Gd (+0,03…0,04) — по записанному протоколу кандидатом не стал.
